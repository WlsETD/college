三個關鍵流程

A邀請連結加入

  1. 管理者建立邀請 → 產生隨機 token，Firestore 只存 tokenHash
  2. 檢視者開 /join/:token，Google 登入
  3. 前端呼叫 Callable joinByInvite(token)
  4. Function 驗 hash、檢查 expiresAt / revokedAt
  5. Admin SDK 寫入 roles[uid]='viewer' 與 userGroups
  6. 導向「選擇我修的科目」

非成員無法通過 Rules 寫 roles，所以這步一定要後端。重新產生 token 只需更新 tokenHash，舊連結自然失效。

B貼上目錄批次建章節

  1. 精靈步驟 2 貼上整段文字
  2. 前端呼叫 parseOutline()（packages/shared）
  3. 即時顯示解析結果，可手動修正
  4. 確認後以 writeBatch() 一次寫入 chapters
  5. order 以 100 為間隔，之後插入不必重排全部

解析是純函式，所有格式變化都在 Vitest 裡測，不依賴 Firestore。

C「下堂課」日期

  1. 取科目 schedule[]（星期 + 節次時間）
  2. 以 Asia/Taipei 的「現在」為基準，不讀瀏覽器時區
  3. 往後掃描候選上課日
  4. 比對 holidays.json，命中就跳過
  5. 回傳第一個成立的日期時間

「下週同一堂」＝同一 weekday + 7 天再跳假日；「明天」不跳假日。三者共用同一個時區工具。

Security Rules 判斷邏輯摘要

綠條＝允許路徑，紅條＝必須拒絕且要有對應測試。實際權限表以你的規格書第 3 節為準，下面是依你訊息推得的版本。

roleOf(gid) = get(/groups/$(gid)).data.roles[request.auth.uid]
唯一權限來源。isMember = roleOf != null；isAdmin = roleOf in ['admin','owner']；isOwner = roleOf == 'owner'。
read: isSignedIn() && appCheck && isMember(gid) && resource.data.deletedAt == null
三種角色都能讀自己群組的未刪除資料。檢視者可讀全部科目，前端才依「我修的科目」過濾。
create / update（科目、章節、內容項目）: isAdmin(gid)
檢視者一律不能寫內容。
allow delete: if false
完全禁止硬刪除。刪除只能是 update 把 deletedAt 由 null 設成 request.time，且不得改回 null。
groups/{gid} 的 roles 欄位: isOwner(gid)
指派／移除管理者。轉移擁有者必須同一次 update 內同時改 ownerUid 與 roles，且新擁有者原本是成員。
members/{uid}.enrolledSubjectIds: request.auth.uid == uid
「我修的科目」只能改自己那筆，不能改別人的。
invites/**: allow read, write: if false
邀請文件完全不經前端，只由 Functions 以 Admin SDK 存取。
storage: isAdmin(gid) && size < 30 * 1024 * 1024 && !contentType.matches('video/.*')
讀取為該群組成員；寫入僅管理者。三個條件各自要有拒絕案例。

01

深色模式要不要做#008751 在深色底無法達 AA。若階段一要支援深色，需要再定一組深色專用的綠／紅；若不做，就鎖定淺色單一主題。

02_test-log 第三部分的 UI 修正你列出的修正我都套了（混合字型、11/22/33、雙重編碼、44×44、硬陰影位移、steps()、16×16 圖示、aria）。但原文若還有其他條目，我看不到。
05
章節樹幾層我假設兩層（章／小節），因為目錄解析的輸出就是兩層。若要支援三層以上，chapters 的 parentId / depth / 排序邏輯要一起改。
06
「缺重點」的定義我暫定為：該章節底下沒有任何 type='keyword' 的未刪除項目。這個定義會直接影響 Firestore 要不要存 hasKeyPoints 快取欄位。
07

08
舊原型要不要沿用D:\專案\歐趴EZ\index.html 是單檔 Vue 3 + Tailwind 的舊版。新專案是 React + Vite + 無 UI 框架，兩者不相容。確認是整個重寫，還是要搬某些邏輯過來。
